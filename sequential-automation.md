# Полная автоматизация с последовательной доставкой

## Как включить

1. Установите браузерный движок, например `python -m pip install patchright`, затем
   `python -m patchright install chromium`. Откройте приложение: `python run.py`.
2. В «Настройках» включите **Полная автоматизация: последовательно и с проверкой прироста**
   и **Автопилот**. Выберите рабочие часы, режим капчи и при необходимости e-mail для площадок.
   Полная автоматизация по умолчанию выключена: настройка существующей установки не меняется сама.
3. Добавьте числовую ссылку сообщества ВК (`vk.ru/club123...`, `vk.com/public123...`), создайте
   цель с нужным **приростом**, например +100 подписчиков. Оставьте программу запущенной.

Автоматическое подтверждение прироста в этой версии поддерживается **только для подписчиков
сообщества ВК с числовым ID**. Личные страницы, короткие имена, Telegram, лайки, просмотры и
другие показатели не запускаются в полном автоматическом режиме: для них нет надёжного счётчика.
Их можно вести в прежнем режиме, выключив полную автоматизацию. Не выключайте защиту, если на
другом сайте по этой ссылке уже идёт заказ.

## Как работает защита от параллельных заказов

1. База атомарно резервирует пару «сообщество + метрика». `vk.ru/club123` и `vk.com/public123`
   считаются одной целью. Новый заказ по той же паре не запустится; другие ссылки не блокируются.
2. До запроса к накруточной площадке программа считывает точное число подписчиков из публичного
   виджета ВК. Если получить точное число нельзя, заказ **не отправляется** и откладывается.
3. После ответа «заказ принят» задача переходит в «жду прирост», а не в «готово». Робот проверяет
   счётчик примерно раз в минуту и требует **два** замера не ниже `до + полный объём сайта`.
4. Только после этого заказ учитывается как выполненный и следующий сайт может запускаться.
   В цель записывается наблюдаемый чистый прирост, а не обещание сайта.
5. Если ответ после нажатия неоднозначен, соединение пропало или приложение закрылось во время
   отправки, результат считается неопределённым. Блокировка сохраняется даже после перезапуска.
   Проверяйте площадку и счётчик вручную. Если убедились, что заказ принят, нажмите «Заказ принят»:
   блокировка сохранится, пока счётчик не подтвердит прирост. Также можно явно нажать «Разблокировать» и
   подтвердить риск: прежний заказ может ещё выполняться, а новый будет с ним пересекаться.

Ожидание автоматически не прекращается по таймеру: медленный сайт может доставить подписчиков
через несколько часов. Ошибка ВК или временное отсутствие счётчика не снимает блокировку.

## Важные ограничения

- Счётчик показывает **общий чистый прирост**: он не умеет отличить результат выбранного сайта
  от естественных подписок, отписок или сторонних заказов. Для надёжности не запускайте другие
  накрутки и избегайте изменений вручную на ту же метрику во время работы.
- Программа не отправляет заявку, если фиксированный объём сайта больше оставшегося объёма цели.
  Планировщик не выдаёт заявку на 20 за заявку на 5. Но внешние площадки и естественный прирост
  могут доставить больше обещанного — точно ограничить итоговое число программа не может.
- Расписание и оценка срока приблизительны: ожидание доставки, доступность сайтов и капчи нельзя
  предсказать. «Полная автоматизация» не гарантирует обход капч или завершение каждого заказа.
  При проблеме потребуется ручное вмешательство.
- Публичный виджет ВК может быть недоступен, отдавать округлённые значения или измениться. В этих
  случаях программа останавливается, а не принимает приблизительную цифру. Для сообщества можно
  дополнительно указать собственный ключ VK API в переменной окружения `VKFREE_VK_TOKEN` до запуска;
  тогда используется `groups.getById` с `members_count`. Ключ не хранится в базе и не передаётся UI.
- Новую защиту нельзя задним числом распространить на заказы, начатые до её включения. Дождитесь их
  окончания перед включением режима. Во время активного заказа переключение режима не отменяет его
  блокировку. Пауза цели не останавливает уже отправленный на внешнюю площадку заказ.

## Проверка

На тестовом сообществе `https://vk.ru/club243157309` публичный виджет показал **47** участников.
Был запущен один реальный запрос на Nakruti.net: параллельный запуск второго сайта программа
заблокировала; Nakruti вернул суточный лимит, заказ отложен. Количество оставалось 47. Поэтому
живое получение +10 и автоматическое снятие блокировки на этой площадке не подтверждены этим тестом.
Позднее виджет показал 46 — число может уменьшаться из-за отписок, поэтому проверка учитывает
чистый прирост, а не гарантирует определение источника подписок.

Полная цепочка пяти заказов по 20, прирост счётчика, двойная проверка, сбой счётчика,
неоднозначная отправка и перезапуск проверены на изолированном тестовом стенде.
