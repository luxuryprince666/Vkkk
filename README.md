# VK Free Farm

Локальный интерфейс для последовательной проверки бесплатных площадок по **реальному счётчику подписчиков** сообщества ВК или публичного Telegram-канала. Принятый заказ, доступная форма и объём из каталога сами по себе не подтверждают прирост.

## Быстрый запуск

Нужен Python 3.9+ и доступ к ВК или Telegram, а также к проверяемым площадкам.

```bash
python3 run.py
# Windows: python run.py, либо run.bat
```

Откройте `http://localhost:8777`, вставьте ссылку в верхнюю форму на вкладке **«Накрутить»** и нажмите **«Накрутить»**. После получения точного исходного счётчика приложение проверяет подходящие включённые услуги по одной. На странице отображаются текущий этап, измерения, попытки, причины отказов, история и выгрузка отчёта в JSON.

Браузерный робот требует отдельно установленного движка и браузера. Например:

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
```

`run.py` также пытается установить недостающие необязательные компоненты в фоне. В некоторых системах может понадобиться виртуальное окружение и системные библиотеки браузера. Видимое окно нужно для ручного решения сложных капч; при запуске без дисплея такое решение может быть недоступно. Успех капчи, доступность форм и доставка подписчиков не гарантируются.

Старый мастер ручных заходов остаётся ниже. Его объёмы и отметки основаны на каталоге или действиях пользователя и **не являются измерением фактического прироста**. Экран «Площадки» проверяет формы, а не доставку подписчиков.

## Как считается результат

1. До обращения к площадке считывается точное число подписчиков. Если счётчик недоступен, заявки не отправляются, а результаты остаются непроверенными.
2. Для каждого сайта снимается собственное исходное значение и повторно обновляется непосредственно перед действием отправки: за время таймера старое число могло измениться. Если новый точный замер не получен, заказ не отправляется и кампания останавливается. Замер и риск возможной отправки сохраняются вместе до клика или POST. Следующий сайт не запускается параллельно.
3. Счётчик регулярно опрашивается минимум пять минут после завершения действий драйвера. Если есть рост, он должен подтвердиться как минимум двумя измерениями; наблюдение продолжается до стабилизации. Для долгих таймеров, в том числе SMM8, опрос идёт и во время работы драйвера.
4. **«Работает»** означает положительное подтверждённое изменение счётчика в окне наблюдения. **«Не работает»** означает отсутствие подтверждённого положительного прироста за окно после подтверждённой заявки. Отписки отображаются как отрицательное чистое изменение, а не как ноль.
5. **«Не проверено»** означает, например, недоступный счётчик, капчу, требуемую регистрацию, неподходящую услугу, отсутствие подтверждённой отправки или остановку. Неизвестный прирост обозначается `—`/`null`, а не нулём.

Время до роста отсчитывается от первого действия, которое могло отправить или запустить заказ, до *первого обнаружения* роста, с точностью до интервала опроса. Таймер площадки входит только если он запущен этим действием; ожидание до него не входит. Если момент действия неизвестен, время не указывается. Если рост не стабилизируется за два часа наблюдения, результат остаётся непроверенным и перехода к следующей площадке нет. Чистый рост счётчика не доказывает причинность: органические подписки, отписки и запоздавшие предыдущие заявки могут исказить оценку. Не запускайте другие заказы на тот же объект параллельно.

Если драйвер, счётчик или программа прервались после возможной отправки, заявка может продолжаться. Автоматический повтор не выполняется. Перед новым запуском вручную проверьте предыдущие заявки и отдельно подтвердите риск перекрытия в предупреждении над отчётом. Подтверждение относится ко всем указанным в предупреждении непроверенным заявкам. Если зависший драйвер не реагирует на остановку, следующий сайт остаётся заблокированным до его фактического завершения. В старых отчётах, где адрес площадки не был сохранён, ссылка остаётся неизвестной.

Для SMMnakrutka робот ждёт, пока сама площадка откроет настоящую форму после пяти минут; видимая вначале форма и кнопка колеса не используются. Перед кликом проверяются бесплатная услуга, её код и поля, заполненные страницей после таймера. При несовпадении отправки нет. По доступной публичной разметке Telegram-страница сейчас показывает несогласованный код услуги, поэтому её автоматический заказ блокируется до проверки.

В доступном скрипте LikeBoom таймер запускается при загрузке страницы, несмотря на текст инструкции о клике. Робот ждёт кнопку и перед заказом проверяет и выбранный, и фактически отправляемый способ оплаты; если бесплатный способ не подтверждён обоими полями, заказ блокируется. Эти сценарии требуют реального сетевого теста: проверка формы не доказывает доставку.

## Ссылки и счётчики

- ВК: публичное сообщество `https://vk.ru/club123…`, `public…`, `event…` или короткое имя, если его удаётся надёжно сопоставить с ID группы. Необязательно можно задать `VKFREE_VK_TOKEN` для VK API; иначе или при сбое API проверяется виджет `#members_count`, а затем мобильная страница (JSON предзагрузки `groups.getById`). Все источники должны подтвердить ID и точное, не округлённое число; фактический источник каждого замера сохраняется. Публичные источники запрашиваются заново с запретом кэширования, но их серверное кэширование исключить нельзя. Если страница изменилась или сеть недоступна, счётчик считается неизвестным, а не берётся из локального снимка.
- Telegram: публичный канал/группа `https://t.me/name`, `https://t.me/s/name` или `@name`. При округлённом публичном счётчике можно настроить `TELEGRAM_BOT_TOKEN`; у бота должны быть необходимые права на чтение количества участников. Измерение сохраняет фактический источник: Bot API либо публичную страницу.
- Личные страницы ВК, отдельные записи и приватные ссылки Telegram в проверяемой кампании не поддерживаются.

Не передавайте токены и конфигурации сторонним лицам. Прокси и подписки, введённые в интерфейсе, сохраняются в локальной SQLite-базе **без шифрования**. В прежней версии каталога были опубликованы учётные данные; если они ещё действуют, их нужно сменить: удаление из текущих файлов не очищает историю Git или существующие базы.

## Прокси, VLESS и Amnezia

В **«Настройки → Сеть и проверка прироста»** можно явно включить собственные доверенные HTTP/SOCKS5-прокси, VLESS или локальный клиент Amnezia/Xray/sing-box. Системный VPN работает как маршрут операционной системы. Для `vless://` нужен установленный `xray` или `sing-box`; без клиента маршрут не будет доступен. Для SOCKS-резерва на стандартном HTTP-клиенте нужен `PySocks`.

Сохраните настройки перед диагностикой. «Проверить счётчик по ссылке» выполняет только чтение, без отправки заказа. Прямое соединение пробуется первым; при явном сетевом сбое до отправки возможен переход на другой разрешённый маршрут. Явные лимиты площадки не обходятся сменой IP. После неоднозначной отправки повтор на другом маршруте запрещён: старый заказ может ещё выполняться.

Используйте только собственные или разрешённые маршруты и соблюдайте условия площадок и применимое законодательство. Подписка загружается только по HTTPS с проверкой публичного адреса, без перенаправлений; доступность прокси и реальную доставку нужно проверять отдельно.

## Запуск из командной строки

```bash
python3 verify_live.py --target https://vk.ru/club123 --output report.txt
python3 verify_live.py --target https://t.me/channelname --json --output report.json
```

Команда может отправлять **реальные заявки** и выполняться долго: минимум пять минут наблюдения на каждый запущенный сайт, плюс таймеры и стабилизация. `Ctrl+C` запрашивает остановку, но не отменяет уже отправленные заказы. Код выхода `2` означает, что проверка не была завершена; код `0` означает завершение кампании, а не то, что все площадки работают. `--acknowledge-risk` используйте только после ручной проверки предыдущих неопределённых заявок.

В `reports/vk-2026-11-19-diagnostic.*` и `reports/vk-counter-fallback-diagnostic.*` сохранены ранние локальные диагностики для `https://vk.ru/club243396555`: из-за сетевого ограничения локального окружения в них заявок не было. Сетевое ограничение не является доказательством того, что площадки не работают.

Более поздняя реальная проверка выполнена через GitHub Actions: [первый запуск](https://github.com/luxuryprince666/Vkkk/actions/runs/44764939761), подробный снимок `reports/vk-live-44764939761.txt` / `.json`. Исходный счётчик был **1**; возможное действие на DoctorSMM не получило распознанного подтверждения, а счётчик в течение первого 15-минутного окна оставался **1 → 1**. Это измеренное отсутствие чистого прироста за окно, не подтверждённый отказ и не доказательство нулевой доставки. DoctorSMM повторно не отправляется.

[Последовательное продолжение](https://github.com/luxuryprince666/Vkkk/actions/runs/44771191791) наблюдало счётчик не менее часа после DoctorSMM, затем начало ранее не отправленные площадки. Его остановили: фразу «подождите» на Avi1 прежняя эвристика ошибочно сочла отказом и перешла к Nakruti.net уже через несколько секунд. Поэтому 1 → 1 за 1,7 секунды после возможной отправки на Avi1 — **не** полноценное окно наблюдения, а происхождение любого последующего прироста неоднозначно. На Nakruti.net следующий замер после 900-секундного окна тоже показал 1; подтверждения заявки нет. Prtut был прерван во время работы драйвера: последний снимок может отставать от остановки и отсутствие отправки не доказано. Подробности — `reports/vk-continuation-44771191791.txt` / `.json` и [восстановленный без заявок архивный снимок](https://github.com/luxuryprince666/Vkkk/actions/runs/44782989466).

Эвристика исправлена: отдельное «подождите» не считается отказом; после любого возможного клика даже текст о лимите или ошибке ссылки не прерывает окно наблюдения и не разрешает автоматический повтор. Из-за возможной поздней доставки прошлых заявок изменение счётчика и время первого обнаружения показываются отдельно от **неизвестного источника доставки**. Одноразовое продолжение эксперимента не отключает стандартную блокировку неоднозначных заказов в приложении.

## Проверки разработки

```bash
python3 -m unittest discover -s tests -v
python3 tests/ui_verify_smoke.py http://127.0.0.1:8777  # нужен запущенный сервер и Playwright
```

Тесты используют фальшивые счётчики, локальные формы и часы: настоящие заявки они не отправляют. UI-smoke подменяет API кампаний в браузере. Браузерные и необязательные зависимости пропускаются, если не установлены. Данные приложения — `data/app.db`, резервные копии — `data/backups/`; для изолированной базы задайте `VKFREE_DATA`.

Сервер по умолчанию слушает только `127.0.0.1`. У него нет системы аутентификации: не открывайте `--host 0.0.0.0` в недоверенной сети. Исторические материалы о формах и планировании находятся в `research/` и `docs/`; это не доказательства текущего прироста. `build_catalog.py` содержит старые условия и по умолчанию создаёт отдельный черновик, не заменяя рабочий `data/catalog.json`.
