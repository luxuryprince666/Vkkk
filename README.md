# VK Free Farm — пульт бесплатной накрутки

Выбрали ссылку, выбрали «+10 подписчиков», нажали «Накрутить» — софт открывает нужную страницу
нужного сайта, кладёт вашу ссылку в буфер обмена и ведёт по шагам, показывая таймер следующего захода.
Дальше он сам держит расписание на 20 рабочих площадках (68 услуг, 54 из них — ВКонтакте), не превышая лимиты,
кулдауны и суточные потолки.

Новое в этой версии: **робот**. Заход на площадку делает сам: открывает страницу заказа, находит поле
ссылки и кнопку, печатает ссылку «по-человечески», ждёт таймер и честно читает ответ страницы
(«заказ принят», «лимит», «неверная ссылка», «капча»). Работает через Patchright / Camoufox /
Nodriver / Playwright — какой установлен, тот и берётся; ещё есть быстрый путь без браузера (curl_cffi).

А ещё **цели**. Пишете «100 лайков и 200 просмотров за 2 дня» — софт сам считает, сколько
успеют бесплатные площадки, раскладывает заходы по времени и доводит до конца. Если невозможно —
честно говорит и показывает реальный максимум. А экран **«Площадки»** показывает, что реально работает
сейчас: где форма жива, где капча, где таймер, и когда площадку проверяли.

Светлый интерфейс из коробки, тёмная тема — переключателем в настройках.
Зависимостей нет: чистый Python 3.9+ (стандартная библиотека). Windows / macOS / Linux.

## Полная автоматизация и последовательные заказы

В «Настройках» включите **полную автоматизацию** и **автопилот**, затем создайте цель.
Для подписчиков сообщества ВК с числовой ссылкой программа перед заказом читает публичный
счётчик ВК и не запускает следующий сайт, пока не увидит полный прирост дважды. Это не
распознаёт источник подписчиков: параллельные внешние заказы и естественный прирост могут
исказить оценку. Для других платформ и метрик режим пока не запускает заявки без надёжного
счётчика. Ошибки и капчи могут потребовать человека; сроки и точное попадание в цель не гарантированы.

Подробнее: [последовательная автоматизация](docs/sequential-automation.md).

## Попытки автоматического решения капч

В настройках включены «Решать капчи автоматически» и «Распознавать капчи с картинки».
Для локального OCR дополнительно установите:

```bash
python -m pip install ddddocr
```

Браузерный движок тоже устанавливается отдельно (например, `python -m pip install playwright` и
`python -m playwright install chromium`). ddddocr работает локально: код с картинки вводится в
поле, но считается лишь предположением до ответа площадки. Робот также ждёт автоматический
токен и пробует видимый чекбокс виджетов; это **не гарантирует прохождение** Turnstile,
reCAPTCHA или hCaptcha, в том числе картинок и сложных интерактивных заданий. Платные сервисы
не подключены. Cloudscraper — отдельный необязательный помощник; автоматический заход его не использует.

Если попытка не удалась и задача запущена с видимым окном, робот ждёт ручное решение в этом
же окне в течение срока из настроек. При фоновом запуске или отсутствии экрана ожидание
невозможно: потребуется ручной заход. Режим «Без капчи» по-прежнему исключает отмеченные
капчей услуги; он не обещает автоматического прохождения всех видов капчи.

На локальных тестовых страницах проверены OCR, искусственный чекбокс и ожидание заглушки.
В реальном пробном заходе SMM8 видимый Turnstile обнаружен и нажат, но токен не получен:
автоматический проход этой защиты **не подтверждён**. Оценки старых живых проверок могут
устаревать. Раздел LikeBoom в старом журнале содержит предположение об e-mail; точная
причина не подтверждена, автоматическое завершение заказа на нём также не подтверждено.

## Запуск

```bash
cd vkfree
python run.py
```

Откроется браузер на `http://localhost:8777`. Дальше всё делается мышкой.

| Ключ | Что делает |
|---|---|
| `--panel` | нативное окно-пульт (tkinter) вместо браузера |
| `--port 9000` | другой порт (если 8777 занят) |
| `--host 0.0.0.0` | доступ с других устройств в сети (телефон, второй ПК) |
| `--no-browser` | не открывать браузер |
| `--export` | выгрузить историю в `exports/history.csv` и выйти |
| `--reset` | снести базу и начать с чистого листа (история пропадёт) |

**Нативный пульт (опционально).** `python run.py --panel` — маленькое окно в стиле интерфейса:
статус, «готово к запуску», переключатель режима, автопилот, журнал и кнопка «Открыть интерфейс».
Полный дашборд всё равно живёт в браузере — окно это пульт, а не замена. Если tkinter или дисплей
недоступны, программа сама откроет браузер и продолжит работать.

Windows: двойной клик по `run.bat`. macOS/Linux: `./run.sh`.

Если `python` не найден — на Windows попробуйте `py run.py`, на macOS/Linux `python3 run.py`.

## Как пользоваться (3 шага)

Главный экран — **«Накрутить»**. Ничего настраивать заранее не нужно: программа сама знает лимиты
всех сайтов и открывает только те окна, где сейчас реально можно взять бесплатное.

1. **Куда накручиваем.** Нажмите на карточку своей ссылки. Если её ещё нет — «+ Добавить ссылку»:
   вставьте адрес, тип (сообщество / личная страница / запись) определится сам, и программа сразу
   отсеет услуги, которые к такому объекту не подходят.
2. **Что накрутить.** Услуги сгруппированы по-человечески: «Подписчики в сообщество», «Лайки на запись»,
   «Просмотры». На карточке написано объёмом: **+10 подписчиков**, сайт и что будете делать
   («откроем страницу — нажмёте сами»). Кнопка «Накрутить» — и пошло.
3. **Сделайте заход.** Программа открывает страницу сайта, кладёт вашу ссылку в буфер обмена и показывает
   четыре пункта: вставить (Ctrl+V), нажать их кнопку, подождать, вернуться и отметить результат.
   Рядом тикает таймер, через сколько сайт снова пустит. «Готово, накрутилось» — заход закрыт,
   следующий встанет в очередь сам. «Не получилось» — задача не пропадёт, её можно повторить.

Две кнопки внизу шага 2: «только доступные сейчас» (по умолчанию включено — видно лишь то, что можно
взять прямо в эту минуту) и «Поставить всё доступное в очередь» — если хотите, чтобы софт сам
растянул заходы по таймерам, пока вы занимаетесь делами.

**Для профи** — вторая строка меню: «Сводка», «Ссылки», «Все услуги», «Журнал», «Настройки».
Это те же данные, но с цифрами, ручной правкой кулдаунов и полным журналом. Новичку туда заходить
не обязательно: всё, что нужно, делается на первом экране.

Вкладка **«Очередь»** — что уже поставлено, что выполняется и что ждёт своего окна; рядом с названием
кнопки видно число задач.

Главное из разбора, что влияет на ожидания:

- **бесплатно = боты или офферы**; выбора «живые из РФ» в бесплатных тарифах не существует ни у одной
  площадки (это есть только в платных услугах);
- у половины площадок капча (reCAPTCHA / Cloudflare Turnstile / hCaptcha) — такие идут только
  в режиме «человек рядом»;
- многие держат **таймер перед заказом** (2–5 минут) и требуют не закрывать вкладку;
- два домена из старого каталога уже мертвы (`feijoa.pro`, `bestsmm.pro`) — софт выключил их сам.

## Робот: заход без вас

По умолчанию площадки работают в режиме **assisted**: софт открывает нужную страницу, копирует вашу
ссылку в буфер, держит таймер, а финальный клик — ваш. Если хотите полный автопилот, включите
у площадки режим **auto** (Настройки → «Автопилот» + режим площадки), и тогда:

1. **Движок.** Возьмите лучший из бесплатных — он убирает следы автоматизации:

```bash
pip install patchright && python -m patchright install chromium   # приоритет №1
pip install "camoufox[geoip]" && python -m camoufox fetch         # Firefox с подменой отпечатка (~1.3 ГБ)
pip install nodriver                                             # Chrome через CDP, нужен локальный Chrome
pip install playwright && python -m playwright install chromium   # обычный, работает всегда
pip install curl_cffi                                            # HTTP с отпечатком Chrome, без браузера
```

Софт сам выберет лучший доступный и покажет, каким работает (экран «Площадки», блок «Робот»).
В Настройках можно закрепить движок вручную.

2. **Проверка.** Кнопка «Робот» у площадки делает сухой прогон: открывает форму, находит поле и
   кнопку и **ничего не отправляет**. Видно, что робот нашёл и на чём споткнулся.
3. **Заходы.** Робот сам печатает ссылку посимвольно с паузами, ждёт, пока площадка включит кнопку,
   нажимает и читает ответ. Найденные селекторы запоминаются — со второго раза быстрее.
4. **Если что-то не так:**

| Ответ робота | Что произойдёт |
|---|---|
| «заказ принят» | заход засчитан |
| «лимит» | заход вернётся в очередь через час (это не ошибка) |
| «неверная ссылка» | задача закроется с причиной |
| «нужна капча» | откроется окно — решите, и заход продолжится (в режиме «Без капчи» заход пропускается) |
| «нужен e-mail / вход» | робот позовёт человека; e-mail для заказов вписывается в Настройках |
| «страница не открылась (404)» | площадка помечается сломанной, после трёх раз выключается на 6 часов |
| «на сегодня использовано» | заход вернётся завтра, а не через час |

Робот также сам: закрывает попапы «Ок, понятно», ждёт таймер площадки (LikeBoom), переключает
площадку в форме заказа на ВК, отмечает обязательные согласия и работает внутри модальных окон.

Капчу робот **не обходит** и не пытается: она решается человеком в открытом окне.

## Режим «Цели»: сколько и за какой срок

Вкладка **«Цели»** — для случая, когда нужен результат, а не отдельный заход.

1. Выберите ссылку (пост, видео — для лайков и просмотров; сообщество или профиль — для подписчиков).
2. Впишите, сколько нужно: например «лайки — 100» и «просмотры — 200». Поле «уже есть» вычитается
   из цели, если часть уже накручена другими способами.
3. Задайте срок: 2 дня, 12 часов — как надо.
4. Нажмите **«Посчитать»**.

Софт ответит одним из трёх:

| Ответ | Что значит |
|---|---|
| **выполнимо** | ёмкости с запасом, заходы размазаны по сроку |
| **впритык** | уложимся, но любая ошибка площадки съест запас |
| **невыполнимо** | показывает реальный максимум за этот срок и предлагает: взять максимум или продлить срок |

Дальше — **«Запустить цель»**. Заходы встают в общую очередь обычными задачами, поэтому работают все
предохранители: кулдауны, суточные лимиты, капча в окне, восстановление после падения. В карточке цели
видно прогресс по каждой метрике, когда следующий заход, что мешает (сломанная площадка, капча в режиме
«Без капчи») и кнопки «Пауза», «+1 день», «Пересчитать», «Удалить».

Чего цель не делает: не имитирует «живую» аудиторию и не обещает, что ВКонтакте не заметит накрутку.
Бесплатные площадки дают ботов и офферы — это их природа, подробности в `research/free-nakrutka-2026.md`.

## Экран «Площадки»: что работает прямо сейчас

Бесплатные панели живут недолго: меняют формы, ставят капчу, умирают. Поэтому софт проверяет их сам.

- **Класс A** — форма простая, без капчи: сюда можно вести робота сразу.
- **Класс B** — без капчи, но есть таймер или очередь: робот ждёт на странице.
- **Класс C** — капча, iframe или общий пул: нужен браузер и человек на капче.

Кнопка **«Проверить»** открывает страницу заказа и смотрит: есть ли поле для ссылки, кнопка отправки,
не появилась ли капча. Площадка выключается из планов только после **двух провалов подряд** — один
сетевой сбой не считается приговором. Фоновая самопроверка делает то же самое сама, раз в полчаса,
по одной площадке, чтобы не выглядеть сканером.

## Подписчики — это два разных продукта: сообщество и личная страница

«Подписчики ВК» — не одна услуга, а две несовместимые: **вступить в сообщество** (группа, паблик, встреча)
и **подписаться на личную страницу человека**. Сервисы их не смешивают, и заход не туда — это слитый впустую слот.

Софт различает их насквозь:

| Где | Что видно |
|---|---|
| **Мои ссылки** | у каждой ссылки есть тип: *сообщество / личная страница / запись*. Программа определяет его по адресу (`vk.com/club123` → сообщество, `vk.com/id777` → страница, `vk.com/wall-1_2` → запись) и подставляет сама; короткие имена вроде `vk.com/moj_pablik` неоднозначны — там тип выбирается вручную одним кликом в списке |
| **Дашборд** | отдельные карточки «Подписчики сообществ» и «Подписчики личных страниц» — с разными остатками, потому что набор услуг разный |
| **Быстрый запуск** | чипы «Подписчики · сообщества» и «Подписчики · личные страницы». Под выбранную ссылку чип подставляется сам, а неподходящие приглушены |
| **Каталог** | колонка «Объект» у каждой услуги и фильтр по нему: сразу видно, какие сайты берут только группы, какие только страницы, а какие не разделяют |
| **Очередь** | рядом со ссылкой — чип объекта, в журнале — «объект: сообщество (услуга: сообщество)» |

Как считается остаток: услуги, которые не разделяют объект (в каталоге помечены «любой объект»),
идут в обе колонки. Только-групповые и только-страничные — строго в свою. Сейчас в каталоге:
3 услуги «только сообщество» (PRSkill «вступившие», LowcostSMM «в группу», AVI1 «в группу»),
1 «только личная страница» (LowcostSMM «на страницу»), 3 «друзья» (это всегда личная страница),
17 универсальных «подписчиков» и 33 услуги под записи (лайки, просмотры, репосты, комментарии, прослушивания).

Планировщик не даст сделать глупость: если ссылка — сообщество, а услуга — «подписчики на страницу»,
задача не создастся, а в предупреждении будет написано почему. Проверку можно выключить
галочкой «Проверять объект» в Настройках — но лучше не выключать.

Каталог — источник истины: если сайт убрать из `data/catalog.json`, при следующей загрузке
каталога (в том числе автоматически при старте) он исчезнет и из базы вместе со своими услугами,
а в журнале появится строка «убрано из базы: N сайтов».

## Три режима работы (переключатель в шапке)

| Режим | Что делает | Участие человека |
|---|---|---|
| **Все сайты** | Работает со всеми услугами. Если сайт показал капчу — открывается окно браузера, капча решается руками, заход продолжается сам | только капча |
| **Без капчи** | Окно браузера не нужно: робот работает скрыто. Непроверенные сайты считаются безопасными; если где-то всё же всплыла капча — программа помечает услугу «капча есть» и в этом режиме больше туда не пойдёт. Рядом появляется кнопка «перевести все сайты в auto» — чтобы режим был полностью автоматическим | нет вообще |
| **С капчей** | Только сайты, помеченные как «капча есть»: окно открывается сразу, чтобы вы были готовы | капча |

Как программа узнаёт про капчу:
- **сама** — робот видит её на странице (reCAPTCHA, hCaptcha, Turnstile, картинка, текст «я не робот») и запоминает;
- **вы** — кнопками «есть / нет / ?» в колонке «Капча» каталога, одной кнопкой на весь сайт или из окна выполнения («На сайте была капча — запомнить»).

## Ручная настройка лимитов

Сайты меняют правила молча, поэтому любую цифру можно переписать под реальность:

- в каталоге кнопка **✎** — объём за заход, кулдаун, заходов в сутки, капча;
- выберите сайт в фильтре — появится панель **«настройка всего сайта»**: один кулдаун на все его услуги и общая метка капчи;
- **очередь пересчитывается автоматически** под новый кулдаун (кнопка «Сохранить и пересчитать очередь»);
- ручные значения хранятся отдельно от каталога: кнопка «Перезагрузить каталог» их не стирает. Вернуть как было — «Вернуть как в каталоге» или «Сбросить ручные настройки» на сайте.

### Режимы выполнения

- **assisted** (по умолчанию, работает везде): софт копирует вашу ссылку в буфер обмена, открывает точную страницу бесплатного заказа и держит таймер кулдауна. Вы вставляете ссылку, жмёте их кнопку и отмечаете «✓» или «✗». Один заход — 10–20 секунд.
Автопилот включён сразу после первого запуска и сам поднимает задачи по расписанию (выключается одним тумблером в Настройках):
- тумблер **«Автопилот сам открывает страницы»** включён (по умолчанию) — в нужный момент софт копирует ссылку, открывает страницу панели и ставит таймер; вам остаётся вставить, нажать их кнопку и подтвердить;
- выключен — задачи просто ждут вас в очереди и ничего не открывается само;
- если человек отошёл и не подтвердил заход, задача через 15 минут возвращается в очередь, а после 3 промахов закрывается как «пропущено» — очередь не залипает.

- **auto** (опционально): робот на Playwright, если он установлен (`pip install playwright && playwright install chromium`). Софт сам подставляет ссылку, жмёт кнопку, ловит капчу и делает скриншот в `logs/screens/`.

Как устроена передача капчи человеку (важно для отказоустойчивости):
1. робот работает в **отдельном потоке** — интерфейс не подвисает, остальные сайты живут своей жизнью;
2. встретив капчу, он ставит задаче статус **«нужна капча»** и держит окно браузера открытым;
3. вы решаете капчу прямо в окне — робот раз в пару секунд проверяет страницу и продолжает сам;
4. если авто-детект не сработал, в очереди есть кнопка **«Я решил капчу»**;
5. не успели за отведённое время (`Ждать решения капчи, сек`, по умолчанию 300) — заход честно падает с понятной причиной и скриншотом, а сайт получает +1 к счётчику неудач.

Пока робот занят одной задачей, вторую он не начнёт — никогда не открывается два окна разом.

Без Playwright приложение не падает: сайты в режиме auto просто вернут понятную ошибку, остальное работает.

**Пароль от ВК нигде не нужен** — только публичная ссылка на профиль/паблик.

## Что внутри под капотом (отказоустойчивость)

- **SQLite + WAL** как единственный источник правды. Убийство процесса, отключение питания, закрытие крышки ноутбука — после перезапуска состояние восстанавливается: зависшие задачи `running → ready`, ничего не теряется и не дублируется.
- **Атомарный claim**: один заход не может выполняться дважды, даже если нажать кнопку в двух вкладках.
- **Суточные лимиты по локальной полуночи**, а не по UTC — «сегодня» всегда по вашему часовому поясу.
- **Кулдаун считается от момента завершения** захода, а не от запроса — так, как это делает сам сайт.
- **Общий слот сайта** (SMM.media и подобные): пока не истечёт кулдаун, софт не отправит второй заход, даже по другой услуге.
- **Breaker**: 3 неудачи по сайту подряд → сайт отключается на 6 часов, остальные продолжают работу.
- **Автобэкапы**: раз в сутки копия базы в `data/backups/` (храним 5 последних).
- **`dry_run`**: тренировка без открытия браузера и без реальных действий.
- **Журнал** всех событий + CSV-экспорт истории.
- **Рабочие часы** (`8-23`, настраивается) — ночью софт не дёргает сайты.
- **Перезагрузка каталога на лету** — поправили `data/catalog.json`, нажали «Перезагрузить каталог», перезапуск не нужен. Ваши отметки «включено/выключено» и режимы при этом сохраняются.

## Структура

```
vkfree/
├── run.py               # точка входа
├── app.py               # внутренний CLI-хелпер
├── build_catalog.py     # генератор data/catalog.json из собранных данных
├── core/
│   ├── db.py            # SQLite, схема, настройки, бэкапы, CSV
│   ├── engine.py        # лимиты, кулдауны, планирование, состояние для UI
│   ├── executor.py      # старт/финиш захода, буфер обмена, браузер, Playwright
│   ├── probe.py         # зонд страницы: поля, кнопки, капча, таймеры, iframe
│   ├── stealth.py       # движки (patchright/camoufox/nodriver/playwright) + curl_cffi + «человечность»
│   ├── drivers.py       # драйвер площадки: найти форму, заполнить, дождаться, нажать, прочитать ответ
│   ├── profiles.py      # профили площадок: класс A/B/C, таймер, самопроверка форм
│   ├── goals.py         # цели: ёмкость под срок, план заходов, прогресс, пересчёт
│   └── server.py        # HTTP API + статика + планировщик + фоновая самопроверка
├── web/index.html       # весь интерфейс (без CDN и интернета)
├── data/                # app.db, catalog.json (у услуг есть subject), backups/
├── exports/             # CSV-история
├── logs/                # логи и скриншоты
└── tests/               # unittest + живые проверки API и интерфейса
```

Проверки:

```bash
python -m unittest discover -s tests -v     # 182 юнит-теста: лимиты, кулдауны, breaker, профили, цели, драйверы
python tests/api_smoke.py                   # 72 проверки API — скрипт сам поднимает сервер на чистой базе
python tests/ui_smoke.py http://127.0.0.1:8777   # 51 проверка интерфейса (нужен Playwright)
```

`api_smoke` ничего не портит: он поднимает свой сервер на временной базе и гасит его за собой.
Тесты драйверов гоняют робота по локальному стенду `tests/fake_panel.py` — страницам-двойникам,
которые ведут себя как разные панели (форма, таймер, капча, лимит, требование e-mail). Настоящие
площадки в тестах не дёргаются: бана не будет.

`ui_smoke` проходит путь новичка мышкой (ссылка → услуга → заход → «Готово»), затем экраны
«Площадки» и «Цели» (расчёт, запуск, прогресс), проверяет, что на экране ровно одна вкладка,
и что в консоли браузера нет ни одной ошибки.

## Ограничения, которые честно стоит знать

- Единицы за заход и кулдауны взяты с самих панелей и из обзоров на момент сборки каталога. Панели меняют правила без предупреждения — софт не может «узнать» новый лимит сам; при отличиях правится `data/catalog.json` (или ждём пересборки каталога).
- Отписки на бесплатных объёмах — норма: 30–100% отписываются за 1–3 дня. Бесплатные подписчики — это «кривая масса» для старта, а не живая аудитория.
- Лимиты часто привязаны к IP: с одного IP на некоторых панелях больше 1–2 заходов не выйдет. Поэтому софт не «долбит» сайт, а растягивает заходы по расписанию.
- Никакие сайты не обходятся CAPTCHA-решателями и не нагружаются параллельными потоками: цель — дожить до конца дня без бана, а не выжать максимум за минуту.
- Расчёт цели опирается на лимиты из каталога и на профили площадок. Если панель поменяет правила, реальная ёмкость окажется меньше — поэтому цель пересчитывается по факту (после каждого захода) и честно говорит, если перестала успевать.
- Ежедневная самопроверка площадок делает один запрос раз в полчаса — не больше, чтобы не привлекать внимания. Полная проверка всех площадок — по кнопке «Проверить все» на экране «Площадки».

## Состав архива

```
vk-free-farm/
├── run.py               ← запускать это
├── run.bat / run.sh     ← то же двойным кликом
├── panel.py             ← нативное окно-пульт (python run.py --panel)
├── README.md            ← этот файл
├── КАК ЗАПУСТИТЬ.txt    ← короткая инструкция
├── core/                ← код: база, лимиты, робот, сервер
├── web/index.html       ← интерфейс (один файл, без интернета и CDN)
├── data/catalog.json    ← каталог лимитов (23 площадки в каталоге, 20 рабочих, 68 услуг, у каждой указан объект)
└── tests/               ← 104 юнит-теста + api_smoke.py + ui_smoke.py
```

База `data/app.db` создастся при первом запуске. Ничего доустанавливать не нужно —
кроме Playwright, если захотите полностью автоматический режим:

```
pip install playwright
playwright install chromium
```
