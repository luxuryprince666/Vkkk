# Что нового: этапы M1 и M2

Коротко: софт научился **сам проверять площадки** и **работать по целям** — «сколько накрутить и за какой срок».

---

## 1. Вкладка «Цели» — главное

Пример: пост, нужно 100 лайков и 200 просмотров за 2 дня.

1. Выбираете ссылку, вписываете «лайки — 100», «просмотры — 200», срок 2 дня.
2. Жмёте «Посчитать». Софт считает **ёмкость**: рабочие часы, кулдауны, суточные лимиты,
   общий пул панелей, класс площадки (A/B/C), уже сделанные сегодня заходы.
3. Ответ всегда один из трёх:
   - **выполнимо** — ёмкости вдвое больше нужного, заходы размазаны по сроку;
   - **впритык** — уложимся, но ошибка одной площадки съест запас;
   - **невыполнимо** — показывает **реальный максимум** за этот срок и две кнопки:
     «взять максимум» и «продлить на N дней».
4. «Запустить цель» — заходы становятся обычными задачами (`tasks.goal_id`), поэтому
   работают все прежние предохранители: кулдауны, лимиты, брейкеры, капча в окне,
   восстановление после падения.

Что видно в карточке цели: прогресс по каждой метрике полосками, «осталось N», время следующего
захода, предупреждения (площадка сломалась, капча в режиме «Без капчи»), кнопки
«Пауза», «Продолжить», «+1 день», «Пересчитать», «Удалить».

Прогресс обновляется **после каждого закрытого захода**. Если по метрике не осталось заходов,
а цель не закрыта — она пересчитывается сама и пишет об этом в журнал.

Чего не делает: не обещает «живую» аудиторию и не обходит капчу. Бесплатные площадки дают ботов
и офферов — это их природа, подробности в `research/free-nakrutka-2026.md`.

---

## 2. Вкладка «Площадки» — что реально работает

Панели живут недолго: меняют формы, ставят капчу, умирают. Теперь софт это отслеживает.

| Класс | Что значит | Как работаем |
|---|---|---|
| **A** | форма простая, капчи нет | робот с первого захода |
| **B** | капчи нет, но есть таймер/очередь | робот ждёт на странице |
| **C** | капча, iframe или общий пул | нужен браузер и человек на капче |

Кнопка «Проверить» открывает страницу заказа и смотрит: есть ли поле для ссылки, кнопка отправки,
не появилась ли капча. Вердикты: `ok` (всё на месте), `js` (форму рисуют скрипты или iframe —
проверим браузером при заходе), `changed` (форма изменилась), `dead` (страница не открывается).

Важная деталь: площадка выключается из планов **только после двух провалов подряд**. Один
сетевой сбой — не приговор, иначе одна плохая секунда выбивала бы рабочую панель.

Фоновая самопроверка берёт **одну** «просроченную» площадку раз в полчаса — не больше,
чтобы не выглядеть сканером. Полная проверка — по кнопке «Проверить все».

Планировщик больше не ставит заходы на сломанные площадки: в плане появится предупреждение
«площадка помечена как нерабочая — заходы не ставлю».

## 3. Что изменилось под капотом

- `core/probe.py` — общий зонд страницы. Раньше разбор был только в CLI-скрипте,

# Этап M3: робот

Коротко: заход на площадку теперь делает робот. Он открывает страницу заказа, сам находит поле
для ссылки и кнопку, печатает ссылку «по-человечески», ждёт, если площадка держит таймер,
нажимает и **честно читает ответ** — а не «вроде нажал, наверное сработало».

## Четыре движка — и все бесплатные

Обычный браузер под управлением автоматики видно по нескольким признакам (`navigator.webdriver`,
CDP-флаги, «пустой» canvas). Бесплатные обходы этого:

| Движок | Что делает | Установка |
|---|---|---|
| **Patchright** | патченный Playwright: те же команды, без следов автоматизации | `pip install patchright` + `python -m patchright install chromium` |
| **Camoufox** | Firefox с подменой отпечатка (canvas, шрифты, WebGL, гео, «Windows») | `pip install "camoufox[geoip]"` + `python -m camoufox fetch` |
| **Nodriver** | Chrome через CDP, без WebDriver | `pip install nodriver` |
| **Playwright** | обычный — работает всегда, если больше ничего нет | `pip install playwright` + `python -m playwright install chromium` |
| **curl_cffi** | вообще без браузера: HTTP с отпечатком TLS настоящего Chrome | `pip install curl_cffi` |

Софт сам берёт лучший установленный (Patchright → Camoufox → Nodriver → Playwright) и **показывает,
чем работает** на экране «Площадки» и в Настройках. Если выбранный вручную движок не запустился —
берётся следующий, а причина видна в диагностике. Всё это опционально: без них остаётся ручной путь.

## Что делает драйвер

1. открывает страницу заказа;
2. проверяет, не 404 ли это (устаревший адрес услуги — частая беда каталога);
3. ищет капчу до всякого ввода;
4. находит поле ссылки: по `name`/`placeholder`/`label`/`aria-label`, потом по «единственному
   широкому текстовому», но не берёт почту и «количество»;
5. печатает ссылку посимвольно с паузами, прокруткой и движениями мыши; если поле не принимает
   печать — вставляет через события `input`/`change` (так нужно React-формам);
6. перечитывает страницу: многие панели рисуют кнопку только после ввода ссылки;
7. подставляет e-mail, если площадка его требует (из Настроек — своих данных не выдумываем);
8. ждёт, пока кнопка станет живой (до 45 с). Если она так и осталась выключенной — это **лимит**,
   а не повод стоять: заход откладывается на час;
9. нажимает кнопку, читает ответ и выносит вердикт.

## Вердикты — на них держится вся честность

| Вердикт | Что значит | Что делает софт |
|---|---|---|
| `ok` | страница подтвердила заказ | заход засчитан, единицы начислены |
| `captcha` | нужна капча | открывает окно человеку; в режиме «Без капчи» — пропускает заход |
| `quota` | «лимит», кнопка выключена | **не ошибка**: заход возвращается в очередь на час |
| `bad_link` | площадка ругается на ссылку | задача закрывается с внятной причиной |
| `need_human` | нужен e-mail, вход, SMS, нестандартная форма | зовёт человека, площадку не ломает |
| `site_broken` | 404, нет формы, сбой драйвера | после трёх раз площадка выключается на 6 часов |

Чтение ответа тоже с приоритетами: «неверная ссылка» важнее «заказ принят» (бывает, что панель
приняла заказ, но ругается на другое поле), а «заказ принят» важнее «капча» — если заявка прошла,
висящая капча заход не отменяет.

## Память площадки

Найденные селекторы сохраняются в профиле площадки (`site_profiles.profile_json.driver`): со второго
захода робот идёт сразу к делу, без поиска. Если селектор перестал работать — ищет заново и
обновляет память. «Забыть» можно, удалив площадку из каталога или через `drivers.forget()`.

## Ограничения, которые остаются

- Капчу робот не обходит — по вашему же требованию: она решается в открытом окне человеком.
- Панели, которые просят вход в аккаунт или SMS, робот не проходит: это `need_human`.
- Если площадка поменяет вёрстку радикально, робот сначала честно скажет «не нашёл», и только
  после трёх таких раз подряд площадка выключится — так один кривой заход не выбивает рабочую панель.
- Установка Camoufox тянет ~1.3 ГБ, Nodriver требует локальный Chrome/Chromium. Это опциональные
  вещи: без них работает Patchright или обычный Playwright.

## Что ещё докручено после первых живыми прогонов

Первые боевые заходы на настоящие панели показали, что «найти поле и нажать кнопку» — это половина
дела. Каждая площадка подкидывает свой сюрприз, и все они теперь отработаны:

| Сюрприз площадки | Как было | Что сделано |
|---|---|---|
| **Таймер вместо формы** (LikeBoom: «нажмите на таймер вверху, ~2 минуты») | «форма изменилась», заход впустую | робот нажимает таймер или, если счётчик уже тикает, ждёт нуля, потом жмёт «Получить бесплатно» и ищет форму |
| **Попап-«читалка»** (nakruti: «Важно знать перед запуском» → «Ок, понятно») | клик уходил в попап, ответ «непонятен» | попап закрывается сам, заказ дожимается той же кнопкой |
| **Капча после нажатия** (smm8: «Checking…» + Cloudflare Turnstile) | «ответ страницы непонятен» | капча распознаётся (iframe Turnstile/reCAPTCHA/hCaptcha, «Checking…» дольше 15 с) → честный вердикт `captcha` |
| **Выбор площадки в форме** (LikeBoom: по умолчанию Telegram) | робот заказал бы «не туда» | площадка переключается на ВК (или Telegram и т.д.) по услуге |
| **Форма-мастер поверх страницы** | поля и кнопки искались «под» модалкой | поиск сужается к открытому окну: поля, согласия, финальная кнопка |
| **Обязательные согласия** | кнопка не срабатывала | робот отмечает «политика конфиденциальности» и «персональные данные» (рассылки — нет) |
| **Рекламный текст как «успех»** (nakruti: «накрутка идёт в общей очереди») | ложное «заказ принят» | вердикт читается по **новому** тексту, появившемуся после клика; «успех» из общего текста больше не засчитывается |
| **«На сегодня всё»** (nakruti: «возвращайтесь завтра») | откладывало на час — и снова впустую | откладывает **до завтра** по тексту страницы |
| **Кнопка из памяти стала чужой** | робот жал «Telegram» из выпадашки | селектор из памяти проверяется: тег, подпись, id/class; чужие кнопки не запоминаются |
| **Скриншот не о том** | снимок уезжал к отзывам внизу страницы | снимок делается с прокруткой к полю/кнопке заказа |
| **Нет экрана (сервер, контейнер)** | headed-браузер падал | если видимое окно не открывается — робот молча работает в фоне |
